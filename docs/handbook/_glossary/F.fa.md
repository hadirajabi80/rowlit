<a id="aggregate-strip"></a>
### aggregate strip — نوار تجمیع
ردیف وضعیتی که Count، Sum، Avg، Min و Max سلول‌های انتخاب‌شده‌ی گرید را نشان می‌دهد. اعشاری‌ها دقیقاً با `BigInt` جمع می‌شوند تا جمع‌ها منحرف نشوند. *مالک: II-13.*

<a id="animation-frame-batching"></a>
### animation-frame batching — دسته‌سازی در فریم
اعمال یکجای رویدادهای ورودی، یک بار در هر فریم صفحه (حدود ۱۶ میلی‌ثانیه). استور نتایج رویدادها را برای هر اجرا صف می‌کند و روی `requestAnimationFrame` تخلیه می‌کند، پس جریان ۱۰۰ هزار سطری یک به‌روزرسانی React در هر فریم هزینه دارد. *مالک: II-13.*

<a id="bidi-rtl-text"></a>
### bidi / RTL text — متن راست‌به‌چپ و دوجهته
متنی که از راست به چپ خوانده می‌شود (فارسی، عربی، عبری) یا جهت‌ها را مخلوط می‌کند. گرید جهت را با اولین نویسه‌ی قوی (UAX #9 یونیکد) تعیین می‌کند و سلول‌های راست‌به‌چپ را با canvas در حالت RTL می‌کشد. *مالک: II-13.*

<a id="bridge"></a>
### bridge — پل (`window.dbstudio`)
شیئی که preload در Electron در اختیار صفحه می‌گذارد. قراردادش در TypeScript `DbStudioBridge` است؛ اعضای تازه اختیاری‌اند تا preloadهای قدیمی‌تر هم کار کنند. *مالک: II-20.*

<a id="bulk-load"></a>
### bulk load — بارگذاری انبوه
نوشتن سطرهای زیاد با مسیر سریع پایگاه داده به‌جای یک INSERT برای هر سطر (`SqlBulkCopy`، `COPY` در PostgreSQL، درج بومی ClickHouse). Rowlit فقط برای حالت‌های append و truncate-insert از آن استفاده می‌کند. *مالک: II-15.*

<a id="bundle-budget"></a>
### bundle budget — بودجه‌ی bundle
سقف رشد مجاز build فشرده‌ی رابط نسبت به یک پایه‌ی ثبت‌شده (در CI: ۱٬۴۰۰ کیلوبایت کل و ۱۲۰ کیلوبایت بار اولیه). قابلیت‌های تازه را به chunkهای تنبل وامی‌دارد. *مالک: II-20.*

<a id="cache-invalidation"></a>
### cache invalidation — ابطال حافظه نهان
دور انداختن یا تازه کردن داده‌ی نهان‌شده وقتی منبع عوض شده است. پس از DDL موتور طرحواره‌های تأثیرپذیرفته را دوباره می‌خواند و نسخه‌شان را بالا می‌برد. *مالک: II-10.*

<a id="canvas-grid"></a>
### canvas grid — گرید canvas
جدولی که روی `<canvas>` کشیده می‌شود نه به‌صورت سطرهای DOM. گرید نتایج Rowlit از glide-data-grid استفاده می‌کند، پس هزینه به سلول‌های دیدنی بستگی دارد نه تعداد سطر. *مالک: II-13.*

<a id="catalog"></a>
### catalog — کاتالوگ
توصیف پایگاه داده از خودش: جدول‌ها، ستون‌ها، کلیدها، viewها، رویه‌ها. از viewهای سیستمی مثل `pg_catalog` یا `sys.*` خوانده می‌شود. *مالک: II-10.*

<a id="catalog-version"></a>
### catalog version — نسخه‌ی کاتالوگ
عدد صحیحی که موتور هر بار کاتالوگ نهان‌شده‌ی یک پایگاه داده را دوباره می‌خواند بالا می‌برد. بخشی از ETag است و هرگز دوباره استفاده نمی‌شود. *مالک: II-10.*

<a id="cell-kind"></a>
### cell kind — نوع سلول
`ColumnKind` ستون (`int`، `decimal`، `string`، `datetime`، `guid`، `binary`، ...) که همراه نتیجه می‌آید. گرید تراز، قالب و ویرایشگر را از آن برمی‌گزیند. *مالک: II-13.*

<a id="cell-viewer"></a>
### cell viewer — نمایشگر سلول
پنل کناری که یک مقدار کامل را نشان می‌دهد و وقتی گرید فقط پیشوند کوتاه‌شده دارد آن را از نتیجه‌ی ذخیره‌شده‌ی موتور می‌گیرد. *مالک: II-13.*

<a id="chord"></a>
### chord — میان‌بر دوضربه‌ای
میان‌بری از دو ضربه‌ی پشت‌سرهم، مثل `Ctrl+K Ctrl+S`. dispatcher برای ضربه‌ی دوم ۱٫۵ ثانیه صبر می‌کند. *مالک: II-20.*

<a id="chunk"></a>
### chunk — تکه‌ی build
فایل جداگانه‌ی build رابط که جدا دانلود می‌شود. `lazy(() => import(...))` برای هر صفحه یا قابلیت یکی می‌سازد. *مالک: II-20.*

<a id="chunked-list"></a>
### chunked list — لیست قطعه‌ای
لیست فقط‌افزودنی ذخیره‌شده در قطعه‌های ثابت (۲٬۰۴۸ عنصر). افزودن هرگز عناصر قدیمی را کپی نمی‌کند، پس نتیجه می‌تواند به میلیون‌ها سطر برسد. *مالک: II-13.*

<a id="code-generation"></a>
### code generation — تولید کد
تبدیل جدول‌ها، viewها و رویه‌ها به کد منبع (C#، Go، TypeScript، Java، Python، SQL، JSON). TypeScript خالص در `ui/src/codegen`. *مالک: II-14.*

<a id="code-splitting"></a>
### lazy loading / code splitting — بارگذاری تنبل / شکستن کد
بارگذاری کد فقط وقتی اولین بار لازم می‌شود. صفحه‌های بزرگ Rowlit کامپوننت `lazy()` هستند تا شروع کوچک بماند. *مالک: II-20.*

<a id="command"></a>
### command — فرمان
کنش کاربر ثبت‌شده با شناسه، عنوان، میان‌بر اختیاری، scope، `when` و `run`. دکمه‌ها، منوها و کلیدها فقط فرمان را فرا می‌خوانند. *مالک: II-20.*

<a id="command-registry"></a>
### command registry — رجیستری فرمان
ماژولی که همه‌ی فرمان‌ها را نگه می‌دارد، میان‌برها را حل می‌کند و تعارض را گزارش می‌دهد. مستقل از فریم‌ورک است تا هر بسته از `commands.ts` خودش ثبت کند. *مالک: II-20.*

<a id="command-scope"></a>
### command scope — دامنه‌ی فرمان
جایی که میان‌بر فعال است: `global`، `editor`، `grid`، `explorer`، `designer`، ... کلید با بالا رفتن از درونی‌ترین `data-command-scope` عنصر focus‌دار حل می‌شود. *مالک: II-20.*

<a id="compare-with-server"></a>
### compare with server — مقایسه با سرور
diff تعریف فعلی شیء روی سرور با متن کنسول «Edit:»، در ویرایشگر diff مربوط به Monaco. *مالک: II-14.*

<a id="component"></a>
### component — کامپوننت
تابع React که UI برمی‌گرداند. Rowlit منطق را در ماژول‌های خالص و استورها نگه می‌دارد و کامپوننت‌ها بیشتر رسم می‌کنند. *مالک: II-20.*

<a id="conditional-request"></a>
### conditional request / 304 — درخواست شرطی
درخواستی با `If-None-Match: <etag>`. اگر چیزی عوض نشده باشد سرور `304 Not Modified` بدون بدنه جواب می‌دهد. *مالک: II-10.*

<a id="connection-guard"></a>
### connection guard — نگهبان اتصال
`ConnectionGuard`: فراخوان‌های کاتالوگ و باز کردن نشست را با مهلت اجرا می‌کند و اتصال مرده را تشخیص می‌دهد تا سروری که ناپدید شده برنامه را قفل نکند. *مالک: II-10.*

<a id="contrast-ratio"></a>
### contrast ratio — نسبت تباین
معیار WCAG برای اختلاف دو رنگ. آزمون‌های Rowlit برای هر پوسته 4.5:1 برای متن و 3:1 برای اجزای UI می‌خواهند. *مالک: II-20.*

<a id="culling"></a>
### culling — حذف نادیدنی‌ها
نکشیدن آنچه بیرون صفحه است. نمودار ER فقط کارت‌ها و یال‌های درون viewport (با حاشیه) را رندر می‌کند. *مالک: II-15.*

<a id="data-tab"></a>
### Data tab — تب Data
تبی که یک جدول یا view را صفحه‌به‌صفحه نشان می‌دهد، با فیلتر و مرتب‌سازی سمت سرور و ویرایش درجا وقتی جدول کلید دارد. *مالک: II-13.*

<a id="ddl-apply-runner"></a>
### DDL apply runner — اجراکننده‌ی اعمال DDL
`DdlApplyRunner`: اسکریپت طراح را روی اتصال اختصاصی، در صورت درخواست در یک تراکنش، اجرا می‌کند و با اندیس دستور ناموفق `DDL_FAILED` می‌اندازد. *مالک: II-14.*

<a id="ddl-preview"></a>
### DDL preview — پیش‌نمایش DDL
اسکریپت تولیدشده به‌صورت متن قابل‌ویرایش، پیش از اعمال. *مالک: II-14.*

<a id="ddl-scripter"></a>
### DDL scripter — اسکریپت‌ساز DDL
`IDdlScripter`: جزء خالص هر فراهم‌کننده که مدل جدول (یا diff دو مدل) را به دستورهای DDL تبدیل می‌کند. *مالک: II-14.*

<a id="decoration"></a>
### decoration — تزئین
علامت دیداری روی متن ویرایشگر (هایلایت، راهنمای درون‌خطی) که جزو متن نیست. Rowlit برای چشمک اجرا و راهنمای پارامتر به کار می‌برد. *مالک: II-12.*

<a id="default-schema"></a>
### default schema — طرحواره‌ی پیش‌فرض
طرحواره‌ای که وقتی نام مشخص نشده به کار می‌رود. موتور برای هر پایگاه داده یکی گزارش می‌کند؛ بعضی گویش‌ها نشست را هم اجازه می‌دهند عوضش کند. *مالک: II-10.*

<a id="dependency"></a>
### dependency — وابستگی (uses / used by)
رابطه‌ی بین اشیا: view از جدول *استفاده می‌کند* (uses)، trigger را جدول *استفاده می‌کند* (used by). موتور یک سطح از هر دو جهت را برمی‌گرداند. *مالک: II-10.*

<a id="describe"></a>
### describe — توصیف
پرسیدن ستون‌های نتیجه‌ی یک `SELECT` از سرور بدون اجرای آن (`SchemaOnly`). *مالک: II-14.*

<a id="design-token"></a>
### design token — توکن طراحی
مقدار طراحی نام‌دار، اینجا یک custom property در CSS مثل `--bg-panel`. رنگ‌ها فقط در فایل‌های پوسته نوشته می‌شوند. *مالک: II-20.*

<a id="designer"></a>
### designer — طراح
ویرایشگر فرم‌محور جدول، view یا رویه که به‌جای SQL دست‌نوشته DDL تولید می‌کند. *مالک: II-14.*

<a id="designer-database"></a>
### designer database — پایگاه داده‌ی طراح
`IDesignerDatabase`: سمت I/O طراح. مدل‌ها را می‌خواند و اسکریپت را روی اتصال کوتاه‌عمر خودش اعمال می‌کند. *مالک: II-14.*

<a id="detached-window"></a>
### detached window — پنجره‌ی جداشده
پنجره‌ی دوم Electron که تب‌های بیرون‌آمده از پنجره‌ی اصلی را نشان می‌دهد. نسخه‌ی خودش از UI را اجرا می‌کند. *مالک: II-20.*

<a id="edit-console"></a>
### edit console — کنسول ویرایش
کنسولی که F4 روی رویه، view، trigger و مانند آن باز می‌کند و اسکریپت قابل‌اجرای دوباره‌ی `CREATE OR ALTER/REPLACE` را دارد. Ctrl+S آن را روی پایگاه داده اعمال می‌کند. *مالک: II-14.*

<a id="editor-group"></a>
### editor group — گروه ویرایشگر
یک نوار تب با تب فعال خودش. تا سه گروه را می‌توان کنار هم یا روی هم شکافت. *مالک: II-20.*

<a id="error-boundary"></a>
### error boundary — مرز خطا
کامپوننت React که خطای رندر زیرشاخه‌اش را می‌گیرد و به‌جای از هم پاشیدن برنامه پنلی نشان می‌دهد. *مالک: II-20.*

<a id="error-report"></a>
### error report — گزارش خطا
CSV سطرهایی که درون‌ریزی نتوانست بنویسد، با شماره‌ی سطر، ستون و پیام. با `GET /import/errors/{jobId}` سرو می‌شود. *مالک: II-15.*

<a id="er-diagram"></a>
### ER diagram — نمودار ER
نمودار موجودیت-رابطه: جدول‌ها کارت، کلیدهای خارجی خط. نمودار Rowlit با کشیدن می‌تواند کلید خارجی بسازد. *مالک: II-15.*

<a id="estimated-vs-actual-plan"></a>
### estimated / actual plan — طرح تخمینی / واقعی
طرح تخمینی انتخاب بهینه‌ساز بدون اجرای دستور است. طرح واقعی آن را اجرا می‌کند و تعداد سطر و زمان واقعی را اضافه می‌کند. *مالک: II-15.*

<a id="etag"></a>
### ETag — اتگ
برچسب کوتاهی که نسخه‌ی یک پاسخ را مشخص می‌کند. ETag در Rowlit هش اتصال، پایگاه داده، نسخه‌ها و نام طرحواره‌هاست با پیشوند epoch هر بار راه‌اندازی. *مالک: II-10.*

<a id="execute-routine-dialog"></a>
### execute routine dialog — پنجره‌ی اجرای رویه
پنجره‌ای که رویه یا تابع را با پارامترهای نوع‌دار (همه به‌صورت bind) فرا می‌خواند و مقدارهای OUT و result setها را نشان می‌دهد. *مالک: II-14.*

<a id="explorer-node"></a>
### explorer node — گره‌ی اکسپلورر
یک ردیف درخت اکسپلورر با شناسه‌ی رشته‌ای پایدار (پیشوندهای `c:`، `d:`، `s:`، `f:`، `o:`، `sq:`). *مالک: II-10.*

<a id="export-scope"></a>
### export scope — دامنه‌ی برون‌ریزی
آنچه برون‌ریزی می‌نویسد: `loaded`، `selection`، `filtered`، `all` یا `rerun`. سه مورد آخر پرس‌وجوی تازه را در موتور بدون سقف سطر اجرا می‌کنند. *مالک: II-15.*

<a id="find-in-database"></a>
### Find in database — جست‌وجو در پایگاه داده
جست‌وجوی نام‌ها، ستون‌ها، کد و اختیاری داده‌ی جدول‌ها روی اتصال‌ها، به‌صورت stream از نوع `db.search`. *مالک: II-10.*

<a id="font-zoom"></a>
### font zoom — بزرگنمایی فونت
تغییر اندازه‌ی فونت ویرایشگر با Ctrl + چرخ (۹ تا ۳۲ px) بدون دست زدن به بزرگنمایی کل پنجره. *مالک: II-12.*

<a id="foreign-catalog"></a>
### foreign catalog — کاتالوگ بیگانه
کاتالوگ نهان‌شده‌ی پایگاه داده‌ی *دیگرِ* همان سرور که IntelliSense برای نام‌هایی مثل `Other.dbo.Orders` به کار می‌برد. *مالک: II-10.*

<a id="format-options"></a>
### format options — گزینه‌های قالب‌بندی
`settings.format`: حالت حروف کلیدواژه و شناسه، تورفتگی، سبک ویرگول، عرض خط، خط‌های خالی. `resolveFormatOptions` اعتبارسنجی و محدودشان می‌کند. *مالک: II-12.*

<a id="formatted-ddl"></a>
### formatted DDL — DDL قالب‌خورده
DDL تب شیء که از قالب‌بند گذشته، با کلیدی برای دیدن متن ذخیره‌شده. *مالک: II-12.*

<a id="formatter"></a>
### formatter — قالب‌بند
کدی که چیدمان SQL را بدون تغییر معنا بازنویسی می‌کند. قالب‌بند Rowlit توکن‌محور است و با بررسی برابری توکن وارسی می‌شود. *مالک: II-12.*

<a id="fuzzy-filter"></a>
### fuzzy filter — فیلتر فازی
تطبیقی که حروف تایپ‌شده فقط باید به همان ترتیب بیایند (`ordl` ← `order_lines`)، با رتبه بر اساس آغاز کلمه‌ها و پیوستگی. *مالک: II-10.*

<a id="ghost-card"></a>
### ghost card — کارت شبح
کارت فقط‌نام جدول در نمودار ER برای جدولی که کلید خارجی به آن اشاره دارد اما بخشی از نمودار نیست. *مالک: II-15.*

<a id="grid-controller"></a>
### grid controller — کنترل‌گر گرید
دستگیره‌ی امری که هر گرید با کلید ثبت می‌کند تا فرمان‌ها بتوانند روی گرید focus‌دار عمل کنند. *مالک: II-13.*

<a id="hook"></a>
### hook — هوک
تابع React با پیشوند `use` که state یا effect به کامپوننت می‌دهد، مثل `useState` یا `useCatalog`. *مالک: II-20.*

<a id="import-dialect"></a>
### import dialect — گویش درون‌ریزی
`ImportDialect`: دانش درون‌ریزی هر موتور: نقل‌قول، نوع‌ها، `CREATE TABLE`، نحو upsert، savepointها، روش انبوه. *مالک: II-15.*

<a id="import-wizard"></a>
### Import Wizard — ویزارد درون‌ریزی
تب شش‌گامی (Source، Format، Target، Columns، Options، Run) که فایل‌های CSV، TSV، XLSX، JSON و NDJSON را در جدول بار می‌کند. *مالک: II-15.*

<a id="keyless-table"></a>
### keyless table — جدول بی‌کلید
جدول بدون کلید اصلی. صفحه‌بندی آن ترتیب پایدار می‌خواهد (`rowid`، `ROWID` یا ستون‌های مرتب) و ویرایش آن هویت سطر. *مالک: II-13.*

<a id="keymap"></a>
### keymap — نقشه‌ی کلید
میان‌برهای مؤثر: پیش‌فرض فرمان‌ها به‌علاوه‌ی بازنویسی‌های کاربر در `settings.ui.keybindings`. *مالک: II-20.*

<a id="keymap-preset"></a>
### keymap preset — پیش‌تنظیم نقشه‌ی کلید
مجموعه‌ای از بازنویسی‌ها که ابزار دیگری را تقلید می‌کند (JetBrains، VS Code، SSMS). *مالک: II-20.*

<a id="language-id"></a>
### language id — شناسه‌ی زبان
نامی که Monaco برای یک زبان به کار می‌برد، اینجا یکی برای هر گویش، مثل `dbstudio-pgsql`. *مالک: II-12.*

<a id="layout-engine-dagre"></a>
### layout engine (dagre) — موتور چیدمان
کتابخانه‌ای که چیدمان لایه‌ای گراف را محاسبه می‌کند. نمودار ER آن را در یک Web Worker اجرا می‌کند. *مالک: II-15.*

<a id="layout-rule"></a>
### layout rule — قاعده‌ی چیدمان
جدول هر گویش در قالب‌بند (کلمه‌های آغاز دستور، کلیدواژه‌های شبیه تابع، بندهای اضافی). *مالک: II-12.*

<a id="lazy-loading"></a>
### lazy loading — بارگذاری تنبل
بارگذاری داده فقط وقتی لازم می‌شود: کاتالوگ وقتی گره‌ی طرحواره باز می‌شود همان طرحواره را بار می‌کند. *مالک: II-10.*

<a id="level-of-detail"></a>
### level of detail (LOD) — سطح جزئیات
کم‌کشیدن هنگام دور شدن. کارت‌های ER زیر zoom برابر 0.45 فقط سرکارت و زیر 0.2 جعبه می‌شوند. *مالک: II-15.*

<a id="local-history"></a>
### local history — تاریخچه‌ی محلی
خط زمانی خصوصی و فشرده‌ی متن هر کنسول، با diff، بازیابی و برچسب. در `local-history.db` موتور ذخیره می‌شود. *مالک: II-12.*

<a id="local-history-snapshot"></a>
### snapshot (local history) — نمای لحظه‌ای تاریخچه‌ی محلی
یک نسخه‌ی ذخیره‌شده از متن ویرایشگر، گرفته‌شده هنگام اجرا، ذخیره، بستن یا هر دو دقیقه هنگام تایپ. snapshot برچسب‌دار هرگز پاک نمی‌شود. *مالک: II-12.*

<a id="lru-cache"></a>
### LRU cache — حافظه نهان LRU
حافظه نهانی که وقتی پر شود کم‌استفاده‌ترین ورودی‌های اخیر را اول دور می‌اندازد. بودجه‌ی حافظه نهان کاتالوگ به‌طور پیش‌فرض ۱۲۸ مگابایت است. *مالک: II-10.*

<a id="lttb"></a>
### LTTB — کاهش نقاط با مثلث‌های بزرگ
Largest-Triangle-Three-Buckets: روش کاهش نمونه که شکل دیداری یک خط بلند را با نقاط کم نگه می‌دارد. *مالک: II-13.*

<a id="mapping"></a>
### mapping — نگاشت
در درون‌ریزی، تخصیص هر ستون هدف به یک ستون مبدأ، ثابت یا عبارت. *مالک: II-15.*

<a id="marker"></a>
### marker — نشانگر
خط موج‌دار با پیام در ویرایشگر. Rowlit مالک‌های جدای markerها برای تشخیص soft، سرور، اجرا و قالب‌بند دارد. *مالک: II-12.*

<a id="menu-model"></a>
### menu model — مدل منو
داده‌ی خالص (`MENUS`، `CONTEXT_MENUS`) که هم منوی بومی و هم منوهای زمینه‌ی درون برنامه از آن ساخته می‌شوند. *مالک: II-20.*

<a id="metadata"></a>
### metadata — فراداده
داده درباره‌ی داده؛ اینجا همان کاتالوگ. *مالک: II-10.*

<a id="minimap"></a>
### minimap — نقشه‌ی کوچک
نمای کلی کوچک (۱۸۰ در ۱۲۰ px) از کل نمودار ER با viewport به‌صورت قاب. *مالک: II-15.*

<a id="monaco"></a>
### Monaco
مؤلفه‌ی ویرایشگر کد Visual Studio Code که برای کنسول‌ها و پیش‌نمایش‌ها در Rowlit جاسازی شده. *مالک: II-12.*

<a id="monaco-action"></a>
### Monaco action — action Monaco
عملیاتی نام‌دار و اختیاری کلیددار که به یک نمونه‌ی ویرایشگر وصل است. Rowlit actionهای کلیددار را با تغییر keymap دوباره ثبت می‌کند. *مالک: II-12.*

<a id="monaco-model"></a>
### model / URI (Monaco) — مدل / URI
مدل متن Monaco همان سند است؛ URI آن (`dbstudio-tab://tab/<id>.sql`) اجازه می‌دهد providerها IntelliSense ویرایشگر درست را پیدا کنند. *مالک: II-12.*

<a id="naming-convention"></a>
### naming convention — قرارداد نام‌گذاری
شیوه‌ی نوشتن شناسه‌ها در کد تولیدشده (`pascal`، `camel`، `snake`، `asIs`)، از جمله مفرد کردن نام جدول‌ها. *مالک: II-14.*

<a id="objects-tab"></a>
### Objects tab — تب Objects
تب دائمیِ اول که اشیای انتخاب اکسپلورر را با تعداد، اندازه و تاریخ فهرست می‌کند. *مالک: II-10.*

<a id="optimistic-concurrency"></a>
### optimistic concurrency — همرسانی خوش‌بینانه
فرض اینکه کسی سطر را عوض نکرده و بررسی هنگام نوشتن. *verify unchanged* در Rowlit مقدارهای قدیمی را به `WHERE` اضافه می‌کند. *مالک: II-13.*

<a id="out-parameter"></a>
### OUT parameter — پارامتر خروجی
پارامتر رویه که خود رویه آن را پس می‌نویسد. Execute routine مقدارهای OUT و مقدار برگشتی را در کارت خروجی‌ها نشان می‌دهد. *مالک: II-14.*

<a id="overlay-editor"></a>
### overlay editor — ویرایشگر روکش
کادر متنی که گرید هنگام ویرایش روی سلول باز می‌کند. در عنصر سراسری `#portal` زندگی می‌کند. *مالک: II-13.*

<a id="paging"></a>
### paging — صفحه‌بندی
خواندن جدول صفحه‌به‌صفحه با `OFFSET/LIMIT` یا `OFFSET/FETCH` و `ORDER BY` پایدار. صفحه‌ی پیش‌فرض ۱٬۰۰۰ سطر است. *مالک: II-13.*

<a id="pending-change"></a>
### pending change — تغییر معلق
ویرایشی در بافر گرید (به‌روزرسانی، درج، حذف) که هنوز ذخیره نشده. با رنگ نشان داده می‌شود و در پیش‌نمایش SQL فهرست می‌گردد. *مالک: II-13.*

<a id="plan-node"></a>
### plan node — گره‌ی طرح
یک عملگر طرح اجرای نرمال‌شده با سطر تخمینی و واقعی، هزینه و هشدارها. *مالک: II-15.*

<a id="plan-reader"></a>
### plan reader — خواننده‌ی طرح
`IPlanReader`: جزء هر فراهم‌کننده که اسکریپت explain و درخت `PlanNode` را می‌سازد. *مالک: II-15.*

<a id="platform-adapter"></a>
### platform adapter — آداپتور پلتفرم
رابط `Platform` که پنهان می‌کند Rowlit در Electron اجرا می‌شود یا مرورگر. *مالک: II-20.*

<a id="postfix-completion"></a>
### postfix completion — تکمیل پسوندی
قالبی که بعد از یک عبارت فعال می‌شود، مثل `Customers.sel`. *مالک: II-12.*

<a id="prisma-schema"></a>
### Prisma schema — طرحواره‌ی Prisma
قالب فایل `schema.prisma`. Rowlit آن را به‌صورت flavor تولیدکننده‌ی TypeScript و فقط برای PostgreSQL تولید می‌کند. *مالک: II-14.*

<a id="procedure-wizard"></a>
### procedure wizard — ویزارد رویه
پنجره‌ای که رویه، تابع، package یا trigger را از قالب هر گویش در یک کنسول ویرایش می‌سازد. *مالک: II-14.*

<a id="quick-filter"></a>
### quick filter — فیلتر سریع
زیرمنوی منوی زمینه‌ی سلول که از مقدار و نوع سلول شرط فیلتر می‌سازد. *مالک: II-13.*

<a id="quit-guard"></a>
### quit guard — نگهبان خروج
بررسی‌ای که پیش از خروج یا بستن پنجره درباره‌ی ویرایش‌های ذخیره‌نشده‌ی گرید و تراکنش‌های باز هشدار می‌دهد. *مالک: II-20.*

<a id="react"></a>
### React
کتابخانه‌ی UI (نسخه‌ی 18.3) که رندرر Rowlit با آن ساخته شده. *مالک: II-20.*

<a id="record-view"></a>
### record view — نمای رکورد
سطر انتخاب‌شده به‌صورت فرم عمودی، با ویرایش و پیمایش کلید خارجی. *مالک: II-13.*

<a id="released-results"></a>
### released results — نتایج آزادشده
نتیجه‌ی پس‌زمینه‌ای که سطرهای بعد از ۱٬۰۰۰ تای اولش برای صرفه‌جویی حافظه دور ریخته شده. *مالک: II-13.*

<a id="reload-vs-re-run"></a>
### reload vs re-run — بارگذاری مجدد در برابر اجرای دوباره
*Reload* سطرهای آزادشده را بی‌اجرای پرس‌وجو از نسخه‌ی ذخیره‌شده‌ی موتور برمی‌گرداند. *Re-run* پرس‌وجو را دوباره اجرا می‌کند. *مالک: II-13.*

<a id="result-chart"></a>
### result chart — نمودار نتیجه
نمودار (میله‌ای، خطی، دایره‌ای، KPI و ...) ساخته‌شده از result set یا تب Data. chunk تنبل با تنظیماتی که برای هر پرس‌وجو به خاطر سپرده می‌شود. *مالک: II-13.*

<a id="result-writer"></a>
### result writer — نویسنده‌ی نتیجه
`IResultWriter`: سطرها را به CSV، TSV، JSON، SQL INSERT، Markdown یا XLSX جاری می‌کند. *مالک: II-15.*

<a id="row-source"></a>
### row source — منبع سطر
خواننده‌ای که سطرها را از فایل درون‌ریزی (CSV، TSV، XLSX، JSON، NDJSON) جاری می‌کند. *مالک: II-15.*

<a id="rowid"></a>
### rowid / ROWID
هویت پنهان سطر در جدول‌های SQLite و Oracle. Rowlit برای صفحه‌بندی و ویرایش جدول‌های بی‌کلید از آن استفاده می‌کند. *مالک: II-13.*

<a id="run-target"></a>
### run target — هدف اجرا
آنچه Run اجرا می‌کند: انتخاب، وگرنه دستور زیر مکان‌نما، وگرنه برای Run script کل سند. *مالک: II-12.*

<a id="saved-filter"></a>
### saved filter — فیلتر ذخیره‌شده
فیلتر نام‌دار گرید که موتور به‌ازای اتصال و امضای ستون‌ها ذخیره می‌کند. *مالک: II-13.*

<a id="saved-query"></a>
### saved query — پرس‌وجوی ذخیره‌شده
پرس‌وجویی که در `queries.json` زیر اتصال، پایگاه داده و طرحواره نگه داشته می‌شود. کنسول بسته‌شده با Ctrl+S به آن پس می‌نویسد. *مالک: II-10.*

<a id="scope-colour"></a>
### scope colour — رنگ دامنه
برچسب رنگی روی پایگاه داده یا طرحواره که در `settings.ui.scopeColors` ذخیره می‌شود. *مالک: II-10.*

<a id="search-path"></a>
### search path — مسیر جست‌وجو
فهرست مرتب طرحواره‌های PostgreSQL برای نام‌های بی‌پیشوند. snapshot آن را برای IntelliSense حمل می‌کند. *مالک: II-10.*

<a id="selector"></a>
### selector — انتخابگر
تابعی که به هوک استور داده می‌شود تا بخشی از state را که کامپوننت لازم دارد برگزیند. *مالک: II-20.*

<a id="server-vs-client-filter"></a>
### server filter vs client filter — فیلتر سرور در برابر کلاینت
فیلتر سرور به `WHERE` پارامتری در پرس‌وجوی تازه تبدیل می‌شود. فیلتر کلاینت روی سطرهای بارگذاری‌شده اعمال می‌گردد. *مالک: II-13.*

<a id="session-restore"></a>
### session restore — بازیابی نشست
در boot، وصل کردن نشست‌های زنده‌ی موتور به تب‌هایی که مالکشان بودند تا تراکنش‌های باز از reload جان به در ببرند. *مالک: II-20.*

<a id="settings-bag"></a>
### settings bag (`settings.ui`) — کیسه‌ی تنظیمات
شیء آزاد در تنظیمات که قابلیت‌ها کلیدهای خودشان را بدون تغییر موتور در آن نگه می‌دارند. *مالک: II-20.*

<a id="snapshot"></a>
### snapshot (catalog) — نمای لحظه‌ای کاتالوگ
JSON فشرده‌ی طرحواره‌های بارگذاری‌شده‌ی یک پایگاه داده، با نسخه و ETag. *مالک: II-10.*

<a id="snippet"></a>
### snippet — قطعه‌کد
قالب SQL قابل‌استفاده‌ی دوباره با پیشوند و جانگهدار، داخلی برای هر گویش یا تعریف‌شده توسط کاربر. *مالک: II-12.*

<a id="snippet-placeholder"></a>
### snippet placeholder — جانگهدار snippet
یک ایستگاه در بدنه‌ی snippet: `$1`، `${1:default}`، `$0`. *مالک: II-12.*

<a id="system-type"></a>
### system type — نوع سیستمی
نوع داده‌ی داخلی که در گروه «System Data Types» در SQL Server فقط‌خواندنی فهرست می‌شود. *مالک: II-10.*

<a id="tab-kind"></a>
### tab kind — نوع تب
`console`، `object` یا `view`؛ تب `view` نام کامپوننتی را می‌دهد که با `registerTabView` ثبت شده. *مالک: II-20.*

<a id="table-diff"></a>
### table diff — تفاوت جدول
`TableDiff.Compute(original, desired)`: ستون‌ها اول با id بعد با نام، قیدها با ساختار، و تولید فهرست تغییر. *مالک: II-14.*

<a id="table-model"></a>
### table model — مدل جدول
`TableModel`: توصیف جدول مستقل از فراهم‌کننده که طراح ویرایشش می‌کند. *مالک: II-14.*

<a id="theme"></a>
### theme — پوسته
مجموعه‌ی نام‌دار بازنویسی توکن‌های طراحی. Rowlit ۷ پوسته‌ی برنامه و ۲۲ پوسته‌ی کد دارد. *مالک: II-20.*

<a id="timeout-deadline"></a>
### timeout / deadline — مهلت
محدودیت زمانی که پس از آن فراخوان رها می‌شود. فراخوان‌های کاتالوگ بسته به نوع ۱۵ ثانیه، ۳۰ ثانیه یا ۵ دقیقه مهلت دارند. *مالک: II-10.*

<a id="token-equality-check"></a>
### token-equality check — بررسی برابری توکن
شبکه‌ی ایمنی قالب‌بند: متن قالب‌خورده دوباره lex می‌شود و باید همان توکن‌ها (جز حروف کلمه‌ها) را داشته باشد وگرنه متن اصلی می‌ماند. *مالک: II-12.*

<a id="toast"></a>
### toast — اعلان
اعلان کوتاه غیرمودال با دکمه‌ی کنش اختیاری. *مالک: II-20.*

<a id="useshallow"></a>
### `useShallow`
کمک Zustand که آرایه یا شیء انتخاب‌شده را سطحی مقایسه می‌کند تا محتوای برابر باعث رندر دوباره نشود. *مالک: II-20.*

<a id="usesyncexternalstore"></a>
### `useSyncExternalStore`
هوک React برای مشترک شدن به state بیرونی. رجیستری فرمان از آن استفاده می‌کند. *مالک: II-20.*

<a id="verify-unchanged"></a>
### verify unchanged — بررسی تغییرنکردن
تنظیم گرید که `UPDATE`/`DELETE` را وادار می‌کند مقدارهای قدیمی را هم بخواهد و تغییر دیگران را تشخیص دهد. *مالک: II-13.*

<a id="virtualisation"></a>
### virtualisation — مجازی‌سازی فهرست
رندر فقط بخش دیدنی یک فهرست بلند. اکسپلورر و گرید هر دو این کار را می‌کنند. *مالک: II-13.*

<a id="web-worker"></a>
### Web Worker
نخ پس‌زمینه‌ی مرورگر. چیدمان ER در یکی از آن‌ها اجرا می‌شود. *مالک: II-15.*

<a id="wire-value"></a>
### wire value — مقدار سیمی
سلول به شکل ارسالی روی پروتکل: اسکالرهای JSON، اعداد بزرگ و اعشاری‌ها به‌صورت رشته، `{ $bin }`، `{ $trunc }`، `{ $cursor }`. *مالک: II-13.*

<a id="workspace-file"></a>
### workspace file — فایل workspace
فهرست ذخیره‌شده‌ی تب‌های باز، متنشان، چیدمان گروه‌ها و تب‌های جداشده. ۸۰۰ میلی‌ثانیه پس از هر تغییر خودکار ذخیره می‌شود. *مالک: II-20.*

<a id="xlsx"></a>
### XLSX
قالب کتاب کار Excel (zip از XML). Rowlit آن را بدون کتابخانه‌ی صفحه‌گسترده می‌خواند و می‌نویسد. *مالک: II-15.*

<a id="upsert"></a>
### upsert — درج یا به‌روزرسانی
درج سطر، یا به‌روزرسانی آن اگر کلیدش از قبل هست (`MERGE`، `ON CONFLICT`، `ON DUPLICATE KEY`). *مالک: II-15.*

<a id="zustand-store"></a>
### Zustand store — استور Zustand
ظرف کوچک state سراسری که با `create(...)` ساخته می‌شود. کامپوننت‌ها با selector مشترک می‌شوند؛ کد دیگر از `getState()` استفاده می‌کند. *مالک: II-20.*
