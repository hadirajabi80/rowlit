# قطعهٔ واژه‌نامه، بستهٔ D (فصل‌های I-14 تا I-17)، فارسی

قالب هر ردیف: لنگر، اصطلاح، معنای مبتدی، نکتهٔ عمیق‌تر، فصل مالک. بستهٔ H این ردیف‌ها را در `fa/glossary.md` (به ترتیب الفبای انگلیسی) ادغام می‌کند. لنگرها همان لنگرهای انگلیسی‌اند.

## I-14 امنیت پایگاه داده

<a id="authentication"></a>
### authentication — احراز هویت
اثبات اینکه کیستید به سرور (گذرواژه، بلیت، گواهی، توکن امضاشده). عمیق‌تر: سرور تعیین می‌کند کدام روش اجرا شود (`pg_hba.conf` در PostgreSQL)؛ روش ضعیف روی اتصال رمزنشده قابل بازپخش یا سرقت است. *مالک: I-14.* ببینید: authorisation، SCRAM، Kerberos.

<a id="authorisation"></a>
### authorisation — مجوزدهی
تصمیم دربارهٔ آنچه موجودیت احرازشده می‌تواند بکند. عمیق‌تر: با نقش، دسترسی، مالکیت و سیاست سطر پیاده می‌شود و اصل حداقل دسترسی طراحی‌اش را هدایت می‌کند. *مالک: I-14.*

<a id="defence-in-depth"></a>
### defence in depth — دفاع چندلایه
استفاده از چند حفاظت مستقل تا شکست یکی کشنده نباشد. عمیق‌تر: احراز هویت، مجوزدهی، رمزنگاری، دفاع در برابر تزریق و ممیزی هرکدام خلأ دیگری را می‌پوشانند. *مالک: I-14.*

<a id="kerberos"></a>
### Kerberos — کربروس
پروتکل احراز هویت شبکه‌ای مبتنی بر بلیت: مرکز توزیع کلید بلیت صادر می‌کند و گذرواژه روی شبکه نمی‌رود. عمیق‌تر: بلیت به SPN سرویس گره می‌خورد؛ «پرش دوگانه» واگذاری محدود می‌خواهد. *مالک: I-14.*

<a id="key-pair-authentication"></a>
### key-pair authentication — احراز هویت با جفت‌کلید
ورود با امضای یک توکن کوتاه‌عمر توسط کلید خصوصی؛ سرور کلید عمومی را دارد. عمیق‌تر: `snowflake_jwt` در Snowflake؛ کلید خصوصی می‌تواند با عبارت عبور رمز شود. *مالک: I-14.*

<a id="oauth"></a>
### OAuth — اوث
چارچوبی که در آن ارائه‌دهندهٔ هویت توکن دسترسی صادر می‌کند و کلاینت به‌جای گذرواژه آن را ارائه می‌دهد. عمیق‌تر: توکن منقضی می‌شود. *مالک: I-14.*

<a id="sso"></a>
### SSO — ورود یکپارچه
یک بار با ارائه‌دهندهٔ هویت وارد شدن و استفادهٔ مجدد از آن برای سرویس‌های بسیار. عمیق‌تر: `externalbrowser` در Snowflake مرورگر را باز می‌کند و مدرکی به پایگاه می‌دهد. *مالک: I-14.*

<a id="scram"></a>
### SCRAM
سازوکار احراز هویت چالش-پاسخ نمک‌دار: دو طرف بدون فرستادن گذرواژه با پاسخ به چالش تازه ثابت می‌کنند آن را می‌دانند. عمیق‌تر: سرور هش نمک‌دار تکرارشده نگه می‌دارد؛ نوع `-PLUS` به کانال TLS گره می‌خورد. *مالک: I-14.*

<a id="pg-hba-conf"></a>
### pg_hba.conf
فایل احراز هویت مبتنی بر میزبان در PostgreSQL: خط‌هایی از (نوع اتصال، پایگاه، کاربر، نشانی، روش). عمیق‌تر: اولین تطبیق برنده است؛ `reject` دری را می‌بندد. *مالک: I-14.*

<a id="principal"></a>
### principal — موجودیت امنیتی
هر چیزی که می‌توان به آن دسترسی داد: کاربر، گروه یا نقش. *مالک: I-14.*

<a id="role"></a>
### role — نقش
بستهٔ نام‌دار دسترسی‌ها که می‌توان به کاربران یا نقش‌های دیگر داد. عمیق‌تر: در PostgreSQL کاربر همان نقش دارای `LOGIN` است؛ Snowflake سلسله‌مراتب نقش دارد. *مالک: I-14.*

<a id="privilege"></a>
### privilege — دسترسی
یک اجازهٔ منفرد مانند `SELECT` روی جدول یا `CREATE TABLE` در schema. عمیق‌تر: دسترسی شیء و دسترسی سیستمی. *مالک: I-14.*

<a id="grant-revoke"></a>
### GRANT / REVOKE — اعطا و سلب دسترسی
`GRANT` دسترسی می‌دهد و `REVOKE` پس می‌گیرد. عمیق‌تر: SQL Server `DENY` هم دارد که بر `GRANT` غلبه می‌کند. *مالک: I-14.*

<a id="least-privilege"></a>
### least privilege — حداقل دسترسی
هر حساب فقط دسترسی‌ای می‌گیرد که کارش لازم دارد. عمیق‌تر: برنامهٔ وب نباید مالک جدول‌ها باشد. *مالک: I-14.*

<a id="row-level-security"></a>
### row-level security — امنیت سطح سطر
شرطی که موتور به هر پرس‌وجو روی جدول می‌افزاید تا کاربر فقط بعضی سطرها را ببیند. عمیق‌تر: مالک و ابرکاربر آن را دور می‌زنند مگر اجبار شود. *مالک: I-14.*

<a id="data-masking"></a>
### data masking — پوشانی داده
برگرداندن نسخهٔ مبدل مقدار به کاربرانی که حق دیدن ندارند. عمیق‌تر: مقدار ذخیره‌شده تغییر نمی‌کند. *مالک: I-14.*

<a id="tls"></a>
### TLS
پروتکلی که اتصال شبکه را رمز می‌کند و احراز می‌دهد (جانشین SSL). عمیق‌تر: محرمانگی، صحت و با راستی‌آزمایی گواهی اصالت سرور. *مالک: I-14.*

<a id="certificate"></a>
### certificate — گواهی
کلید عمومی به‌علاوهٔ هویت (نام میزبان) که یک مرجع صدور گواهی امضا کرده است. عمیق‌تر: کلاینت زنجیره، تاریخ اعتبار و نام میزبان را می‌سنجد. *مالک: I-14.*

<a id="certificate-authority"></a>
### certificate authority — مرجع صدور گواهی (CA)
سازمانی که کلاینت‌ها به امضایش روی گواهی‌ها اعتماد دارند. عمیق‌تر: `verify-ca` فقط زنجیره را می‌سنجد، `verify-full` نام میزبان را هم. *مالک: I-14.*

<a id="man-in-the-middle"></a>
### man-in-the-middle — حملهٔ مرد میانی
مهاجمی که میان کلاینت و سرور ترافیک را رله یا دستکاری می‌کند. عمیق‌تر: رمزنگاری بدون راستی‌آزمایی گواهی جلویش را نمی‌گیرد. *مالک: I-14.*

<a id="encrypt-trustservercertificate"></a>
### Encrypt / TrustServerCertificate
گزینه‌های اتصال SQL Server: `Encrypt` (Optional، Mandatory، Strict) رمزنگاری را تعیین می‌کند؛ `TrustServerCertificate=true` اعتبارسنجی گواهی را رد می‌کند. عمیق‌تر: Strict همان TDS 8.0 است. *مالک: I-14.*

<a id="sslmode"></a>
### sslmode
تنظیم TLS در PostgreSQL: `disable`، `allow`، `prefer`، `require`، `verify-ca`، `verify-full`. عمیق‌تر: فقط `verify-full` جلوی جعل هویت را می‌گیرد. *مالک: I-14.*

<a id="tde"></a>
### TDE — رمزنگاری شفاف داده
رمزنگاری فایل‌های داده زیر لایهٔ SQL، نامرئی برای برنامه‌ها. عمیق‌تر: از دیسک و پشتیبان دزدیده‌شده محافظت می‌کند نه از کاربر مجاز؛ کلید باید جای دیگر باشد. *مالک: I-14.*

<a id="sql-injection"></a>
### SQL injection — تزریق SQL
وادار کردن برنامه به اجرای SQL دلخواه مهاجم چون ورودی در متن دستور چسبانده شده. عمیق‌تر: برای مقدار با پارامتر و برای شناسه با فهرست مجاز حل می‌شود. *مالک: I-14.*

<a id="parameterised-query"></a>
### parameterised query — پرس‌وجوی پارامتری
متن SQL با جانگهدار که جدا از مقدارها فرستاده می‌شود (دستور آماده هم می‌گویند). عمیق‌تر: بعضی درایورها (MySqlConnector) سمت کلاینت escape می‌کنند. *مالک: I-14.*

<a id="bind-variable"></a>
### bind variable — متغیر پیوندی
جانگهداری در دستور که هنگام اجرا پر می‌شود. عمیق‌تر: نحو در هر گویش فرق دارد (`@name`، `:name`، `$1`، `?`، `{name:Type}`)؛ فصل I-17 سبک‌ها را فهرست می‌کند. *مالک: I-14 (سبک‌ها: I-17).*

<a id="audit"></a>
### audit — ممیزی
ثبتی دست‌نخورده از ورودها، تغییرها و خواندن‌ها. عمیق‌تر: لاگ را بیرون از میزبان بفرستید؛ معنادار ممیزی کنید نه همه‌چیز. *مالک: I-14.*

## I-15 OLTP در برابر OLAP و موتورهای ستونی

<a id="oltp"></a>
### OLTP — پردازش تراکنشی
خواندن و نوشتن‌های کوچک و بسیار روی چند سطر کامل. عمیق‌تر: تأخیر کم و ACID می‌خواهد؛ ذخیره‌سازی سطری. *مالک: I-15.*

<a id="olap"></a>
### OLAP — پردازش تحلیلی
پرس‌وجوهای بزرگ و کم که چند ستون از سطرهای بسیار را می‌پویند. عمیق‌تر: توان عبوری می‌خواهد؛ ذخیره‌سازی ستونی و طرح ستاره‌ای. *مالک: I-15.*

<a id="htap"></a>
### HTAP
پردازش ترکیبی تراکنشی و تحلیلی: یک سامانه هر دو را سرویس می‌دهد. عمیق‌تر: معمولاً دو نسخهٔ سطری و ستونی هم‌گام. *مالک: I-15.*

<a id="row-store"></a>
### row store — ذخیره‌سازی سطری
ذخیره‌سازی که همهٔ فیلدهای سطر را کنار هم نگه می‌دارد. عمیق‌تر: برای گرفتن یا به‌روزرسانی سطر کامل بهترین است. *مالک: I-15.*

<a id="column-store"></a>
### column store — ذخیره‌سازی ستونی
ذخیره‌سازی که همهٔ مقدارهای یک ستون را کنار هم نگه می‌دارد. عمیق‌تر: فقط ستون‌های لازم را می‌خواند و خوب فشرده می‌شود؛ برای دسترسی تک‌سطر گران است. *مالک: I-15.*

<a id="compression-rle-dictionary-delta"></a>
### compression (RLE / dictionary / delta) — فشرده‌سازی
RLE مقدار و تعداد تکرارش را ذخیره می‌کند؛ dictionary مقدارها را با کد کوچک جایگزین می‌کند؛ delta تفاوت‌ها را. عمیق‌تر: پس از آن LZ4 یا ZSTD؛ `CODEC(Delta, ZSTD)` در ClickHouse. *مالک: I-15.*

<a id="vectorised-execution"></a>
### vectorised execution — اجرای برداری
عملگرها به‌جای یک سطر، دسته‌ای از مقدارهای یک ستون را پردازش می‌کنند. عمیق‌تر: فراخوانی کمتر، دوستدار حافظهٔ نهان، SIMD. *مالک: I-15.*

<a id="late-materialisation"></a>
### late materialisation — تحقق دیرهنگام
به تعویق انداختن ساخت سطر کامل تا پس از فیلتر. عمیق‌تر: `PREWHERE` در ClickHouse. *مالک: I-15.*

<a id="mergetree"></a>
### MergeTree
خانوادهٔ اصلی موتور جدول ClickHouse: partهای مرتب و تغییرناپذیر که در پس‌زمینه ادغام می‌شوند. عمیق‌تر: گونه‌های Replacing، Summing، Aggregating، Collapsing. *مالک: I-15.*

<a id="part"></a>
### part — پارت
تکهٔ مرتب و تغییرناپذیر جدول MergeTree که یک درج یا ادغام نوشته. عمیق‌تر: نام `partition_minblock_maxblock_level`. *مالک: I-15.*

<a id="granule"></a>
### granule — گرانول
واحد نمایهٔ تُنُک ClickHouse: پیش‌فرض ۸٬۱۹۲ سطر. عمیق‌تر: پرس‌وجو granule کامل می‌خواند. *مالک: I-15.*

<a id="partition-clickhouse"></a>
### partition (ClickHouse) — پارتیشن
تقسیم درشت جدول (مثلاً ماهانه) برای مدیریت داده و هرس. عمیق‌تر: part هرگز از پارتیشن عبور نمی‌کند؛ پارتیشن بسیار زیان دارد. *مالک: I-15.*

<a id="merge"></a>
### merge — ادغام
ترکیب پس‌زمینهٔ partهای کوچک در بزرگ‌تر. عمیق‌تر: تقویت نوشتن؛ معناشناسی Replacing و Summing را تعیین می‌کند. *مالک: I-15.*

<a id="mutation"></a>
### mutation — جهش
`ALTER TABLE … UPDATE/DELETE` ناهمگام در ClickHouse که partهای درگیر را بازنویسی می‌کند. عمیق‌تر: در `system.mutations` پیگیری می‌شود. *مالک: I-15.*

<a id="materialized-view-clickhouse"></a>
### materialized view (ClickHouse) — نمای مادی‌شده
محرک درجی که پرس‌وجو را روی هر بلوک درج‌شده اجرا می‌کند و نتیجه را در جدول مقصد می‌نویسد. عمیق‌تر: نسبت به سطرهای پیشین و به‌روزرسانی/حذف کور است. *مالک: I-15.*

<a id="dictionary-clickhouse"></a>
### dictionary (ClickHouse) — دیکشنری
جدول کلید‌به‌ویژگی درون حافظه که از یک منبع تازه می‌شود و با `dictGet` خوانده می‌شود. عمیق‌تر: برای جست‌وجوی کوچک جای join. *مالک: I-15.*

<a id="projection-clickhouse"></a>
### projection (ClickHouse) — پروجکشن
نسخهٔ پنهان با مرتب‌سازی یا تجمیع متفاوت درون هر part. عمیق‌تر: بهینه‌ساز خودکار انتخاب می‌کند. *مالک: I-15.*

<a id="micro-partition"></a>
### micro-partition — ریزپارتیشن
فایل ذخیره‌سازی ستونی تغییرناپذیر Snowflake (حدود ۵۰ تا ۵۰۰ مگابایت پیش از فشرده‌سازی). عمیق‌تر: فرادادهٔ کمینه/بیشینه هرس را ممکن می‌کند. *مالک: I-15.*

<a id="virtual-warehouse"></a>
### virtual warehouse — انبار مجازی
خوشهٔ محاسباتی Snowflake که اندازه‌اش را تعیین می‌کنید و مستقل از ذخیره‌سازی روشن/معلق می‌شود. عمیق‌تر: تا وقتی روشن است ثانیه‌ای هزینه دارد. *مالک: I-15.*

<a id="time-travel"></a>
### time travel — سفر در زمان
پرس‌وجو یا بازیابی داده به‌صورتی که در گذشته بود. عمیق‌تر: Snowflake ۱ تا ۹۰ روز تاریخچه و بعد ۷ روز fail-safe. *مالک: I-15.*

<a id="stage"></a>
### stage
مکانی نام‌دار برای فایل‌ها که `COPY INTO` به کار می‌برد (Snowflake). عمیق‌تر: داخلی یا بیرونی. *مالک: I-15.*

<a id="stream-snowflake"></a>
### stream (Snowflake)
شیئی که تغییرات جدول را از آخرین مصرف ثبت می‌کند. عمیق‌تر: ضبط تغییر داده (CDC) داخلی. *مالک: I-15.*

<a id="task-snowflake"></a>
### task (Snowflake)
دستور SQL زمان‌بندی‌شده یا فعال‌شده با stream. عمیق‌تر: taskها می‌توانند گراف وابستگی بسازند. *مالک: I-15.*

<a id="pipe"></a>
### pipe
شیء Snowflake (Snowpipe) که فایل‌ها را با رسیدن به stage پیوسته بار می‌کند. *مالک: I-15.*

<a id="star-schema"></a>
### star schema — طرح ستاره‌ای
جدول واقعیت که جدول‌های بُعد دورش را گرفته‌اند. عمیق‌تر: بُعدهای غیرنرمال؛ «دانه‌برفی» آن‌ها را نرمال می‌کند. *مالک: I-15.*

<a id="fact-dimension-table"></a>
### fact / dimension table — جدول واقعیت / بُعد
جدول واقعیت رویدادهای قابل اندازه‌گیری را دارد؛ جدول‌های بُعد زمینه را توصیف می‌کنند. عمیق‌تر: اول دانه (grain) را تعیین کنید. *مالک: I-15.*

<a id="data-warehouse"></a>
### data warehouse — انبار داده
پایگاهی سازمان‌یافته برای تحلیل که از سامانه‌های عملیاتی تغذیه می‌شود. عمیق‌تر: ELT اول داده خام را بار می‌کند. *مالک: I-15.*

<a id="lakehouse"></a>
### lakehouse — لیک‌هاوس
دریاچهٔ داده از فایل‌های ستونی (Parquet) با قالب جدول تراکنشی (Iceberg، Delta، Hudi). عمیق‌تر: چند موتور یک نسخه را با ACID پرس‌وجو می‌کنند. *مالک: I-15.*

<a id="columnstore"></a>
### columnstore — ستون‌انبار
نمایهٔ ستونی SQL Server (خوشه‌ای یا غیرخوشه‌ای) در row groupها. عمیق‌تر: batch mode، segment elimination، delta store، tuple mover. *مالک: I-15.*

## I-16 خانواده‌های NoSQL و درون آن‌ها

<a id="nosql"></a>
### NoSQL
برچسب سست برای پایگاه‌های غیررابطه‌ای ساخته‌شده برای مقیاس، طرح انعطاف‌پذیر یا الگوی دسترسی تخصصی. *مالک: I-16.*

<a id="key-value-store"></a>
### key-value store — ذخیره‌ساز کلید-مقدار
پایگاهی که کلید را به مقدار نگاشت می‌کند. عمیق‌تر: مقدارهای Redis نوع دارند؛ دسترسی با کلید. *مالک: I-16.*

<a id="document-store"></a>
### document store — ذخیره‌ساز سندمحور
پایگاه سندهای تو‌در‌توی شبیه JSON. عمیق‌تر: MongoDB؛ embed یا ارجاع. *مالک: I-16.*

<a id="wide-column-store"></a>
### wide-column store — ذخیره‌ساز ستون‌گسترده
پایگاهی که کلید پارتیشن به سطرهای مرتب با ستون‌های انعطاف‌پذیر می‌رسد. عمیق‌تر: Cassandra؛ به معنای OLAP ستون‌انبار نیست. *مالک: I-16.*

<a id="search-engine"></a>
### search engine — موتور جست‌وجو
سامانه‌ای حول نمایهٔ معکوس برای جست‌وجوی متنی با رتبه‌بندی ارتباط. عمیق‌تر: Elasticsearch، OpenSearch، Solr. *مالک: I-16.*

<a id="event-log"></a>
### event log — لاگ رویداد
دنبالهٔ مرتب، فقط‌افزودنی و قابل بازپخش رویدادها. عمیق‌تر: Kafka. *مالک: I-16.*

<a id="bson"></a>
### BSON
قالب دودویی JSON در MongoDB با نوع‌های بیشتر. عمیق‌تر: `ObjectId`، `Decimal128`، تاریخ، دودویی؛ حد ۱۶ مبی‌بایت. *مالک: I-16.*

<a id="extended-json"></a>
### Extended JSON
شکل متنی BSON که نوع‌ها را نگه می‌دارد (`{"$oid": …}`، `{"$numberLong": …}`). عمیق‌تر: حالت canonical و relaxed. *مالک: I-16.*

<a id="_id"></a>
### _id
فیلد کلید یکتای هر سند MongoDB. عمیق‌تر: پیش‌فرض `ObjectId` (۴ بایت زمان، ۵ بایت تصادفی، ۳ بایت شمارنده). *مالک: I-16.*

<a id="replica-set"></a>
### replica set
گروه MongoDB از یک primary و چند secondary با داده یکسان. عمیق‌تر: انتخابات هنگام خرابی؛ write concern ماندگاری را تعیین می‌کند. *مالک: I-16.*

<a id="oplog"></a>
### oplog
collection محدودشدهٔ تغییرات (`local.oplog.rs`) که secondaryها بازپخش می‌کنند. عمیق‌تر: ورودی‌ها خودتوان‌اند؛ change stream از آن استفاده می‌کند. *مالک: I-16.*

<a id="aggregation-pipeline"></a>
### aggregation pipeline — خط لولهٔ تجمیع
پرس‌وجوی MongoDB به‌صورت آرایه‌ای از مرحله‌ها (`$match`، `$group`، `$lookup`، …). عمیق‌تر: `$match` و `$sort` را اول بگذارید. *مالک: I-16.*

<a id="change-stream"></a>
### change stream — جریان تغییر
اشتراک در تغییرات یک collection در MongoDB. عمیق‌تر: replica set می‌خواهد. *مالک: I-16.*

<a id="partition-key"></a>
### partition key — کلید پارتیشن
در Cassandra بخشی از کلید اصلی که تعیین می‌کند سطر در کدام گره‌ها ذخیره شود. عمیق‌تر: به توکن هش می‌شود؛ پرس‌وجو باید آن را نام ببرد. *مالک: I-16.*

<a id="clustering-key"></a>
### clustering key — کلید خوشه‌بندی
در Cassandra بخشی از کلید اصلی که ترتیب سطرها درون پارتیشن را تعیین می‌کند. *مالک: I-16.*

<a id="token-ring"></a>
### token ring — حلقهٔ توکن
فضای هش Cassandra (−2⁶³ تا 2⁶³−1) که بین گره‌ها تقسیم شده. عمیق‌تر: گره‌های مجازی مالکیت را پخش می‌کنند. *مالک: I-16.*

<a id="replication-factor"></a>
### replication factor — ضریب همانندسازی
تعداد گره‌هایی که هر پارتیشن را ذخیره می‌کنند. عمیق‌تر: برای هر keyspace؛ در تولید معمولاً ۳. *مالک: I-16.*

<a id="consistency-level"></a>
### consistency level — سطح سازگاری
تعداد replicaهایی که باید به خواندن یا نوشتن Cassandra پاسخ دهند. عمیق‌تر: `R + W > RF` سازگاری قوی می‌دهد. *مالک: I-16.*

<a id="lsm-tree"></a>
### LSM tree — درخت LSM
درخت ادغام ساختارلاگی: نوشتن به لاگ و جدول درون حافظه می‌رود، به فایل‌های مرتب تغییرناپذیر flush می‌شود و بعداً ادغام می‌شود. *مالک: I-16.*

<a id="memtable"></a>
### memtable
جدول مرتب درون حافظه که پیش از flush نوشتن را می‌گیرد. *مالک: I-16.*

<a id="sstable"></a>
### SSTable
فایل مرتب تغییرناپذیر که از memtable flush شده. عمیق‌تر: همراه فایل‌های نمایه، خلاصه و فیلتر Bloom. *مالک: I-16.*

<a id="compaction"></a>
### compaction
ادغام پس‌زمینهٔ SSTableها. عمیق‌تر: size-tiered، leveled، time-window، unified. *مالک: I-16.*

<a id="tombstone"></a>
### tombstone — سنگ‌قبر
نشانه‌ای که داده حذف‌شده را در ذخیره‌ساز فایل تغییرناپذیر پنهان می‌کند. عمیق‌تر: به مدت `gc_grace_seconds` (پیش‌فرض ۱۰ روز) می‌ماند؛ tombstone زیاد خواندن را کند می‌کند. *مالک: I-16.*

<a id="commitlog"></a>
### commitlog
فایل write-ahead ترتیبی Cassandra برای بازیابی خرابی. عمیق‌تر: پیش‌فرض هر ۱۰ ثانیه همگام می‌شود. *مالک: I-16.*

<a id="inverted-index"></a>
### inverted index — نمایهٔ معکوس
نگاشتی از هر واژه به سندهایی که آن را دارند. عمیق‌تر: پایهٔ جست‌وجوی متن کامل؛ امتیازدهی BM25. *مالک: I-16 (همچنین I-07).*

<a id="analyzer"></a>
### analyzer — تحلیل‌گر
خط لوله‌ای که متن را به واژه می‌برد (فیلتر نویسه، tokenizer، فیلتر token). عمیق‌تر: هنگام نمایه‌سازی و جست‌وجو یکسان. *مالک: I-16.*

<a id="mapping"></a>
### mapping — نگاشت
اعلان نوع و شیوهٔ نمایه‌سازی هر فیلد در Elasticsearch. عمیق‌تر: `text` در برابر `keyword`. *مالک: I-16.*

<a id="shard-replica-elasticsearch"></a>
### shard / replica (Elasticsearch) — شارد / replica
shard یک نمایهٔ Lucene است که بخشی از نمایه را دارد؛ replica نسخهٔ آن است. عمیق‌تر: تعداد shard اصلی هنگام ساخت ثابت می‌شود. *مالک: I-16.*

<a id="segment"></a>
### segment — قطعه
نمایهٔ کوچک تغییرناپذیر درون shard در Lucene. عمیق‌تر: حذف علامت‌گذاری است؛ ادغام قطعه‌ها را بازنویسی می‌کند. *مالک: I-16.*

<a id="refresh"></a>
### refresh
جست‌وجوپذیر کردن سندهای بافرشده با نوشتن قطعهٔ تازه (پیش‌فرض هر ۱ ثانیه). عمیق‌تر: دلیل تقریباً بلادرنگ بودن Elasticsearch. *مالک: I-16.*

<a id="seq-no-primary-term"></a>
### seq_no / primary_term
شمارنده‌های Elasticsearch که با هر نوشتن برمی‌گردند. عمیق‌تر: `if_seq_no` و `if_primary_term` همزمانی خوش‌بینانه می‌دهند. *مالک: I-16.*

<a id="broker"></a>
### broker
سرور Kafka. عمیق‌تر: partition یک broker leader و replicaهای دنبال‌کننده دارد. *مالک: I-16.*

<a id="topic"></a>
### topic — تاپیک
جریان نام‌دار رکوردها در Kafka که به partitionها تقسیم می‌شود. *مالک: I-16.*

<a id="partition-kafka"></a>
### partition (Kafka)
دنبالهٔ مرتب و فقط‌افزودنی رکوردها درون topic. عمیق‌تر: ترتیب فقط درون partition تضمین است؛ کلید partition را تعیین می‌کند. *مالک: I-16.*

<a id="offset"></a>
### offset
جایگاه رکورد در partitionش. عمیق‌تر: مصرف‌کننده‌ها offset را در `__consumer_offsets` commit می‌کنند. *مالک: I-16.*

<a id="consumer-group"></a>
### consumer group — گروه مصرف‌کننده
مصرف‌کننده‌های دارای `group.id` مشترک که partitionهای topic را بین خود تقسیم می‌کنند. عمیق‌تر: هر partition در هر لحظه یک مصرف‌کننده دارد. *مالک: I-16.*

<a id="consumer-lag"></a>
### consumer lag — تأخیر مصرف
`log end offset − committed offset`: رکوردهای هنوز پردازش‌نشده. *مالک: I-16.*

<a id="isr"></a>
### ISR — replicaهای همگام
replicaهای Kafka که به leader رسیده‌اند. عمیق‌تر: `acks=all` منتظر ISR می‌ماند؛ `min.insync.replicas` کف را تعیین می‌کند. *مالک: I-16.*

<a id="retention"></a>
### retention — نگه‌داشت
قاعدهٔ حذف داده قدیمی Kafka بر اساس سن یا اندازه (پیش‌فرض ۷ روز). *مالک: I-16.*

<a id="log-compaction"></a>
### log compaction — compaction لاگ
سیاست Kafka که فقط آخرین رکورد هر کلید را نگه می‌دارد. عمیق‌تر: مقدار null (tombstone) کلید را برمی‌دارد. *مالک: I-16.*

<a id="kraft"></a>
### KRaft
حدنصاب Raft درونی Kafka برای فراداده که جای ZooKeeper را می‌گیرد (در Kafka 4.0 برداشته شد). *مالک: I-16.*

<a id="schema-registry"></a>
### Schema Registry
سرویسی که طرح‌های نسخه‌دار پیام‌های Kafka را نگه می‌دارد و سازگاری را اعمال می‌کند. عمیق‌تر: پیام بایت جادویی و شناسهٔ ۴ بایتی طرح دارد. *مالک: I-16.*

<a id="resp"></a>
### RESP
پروتکل سریال‌سازی Redis: نوع‌های پیشوندی با قاب‌بندی `\r\n` (`+ - : $ *`). عمیق‌تر: RESP2 رایج است؛ RESP3 نقشه و push اضافه می‌کند. *مالک: I-16.*

<a id="sentinel"></a>
### Sentinel
فرایندهای ناظر Redis که primary از کار افتاده را تشخیص می‌دهند و replica ارتقا می‌دهند. عمیق‌تر: مبتنی بر quorum؛ برای یک shard داده. *مالک: I-16.*

<a id="redis-cluster"></a>
### Redis Cluster
مقیاس افقی Redis با ۱۶٬۳۸۴ hash slot روی چند master. عمیق‌تر: سازگاری قوی ندارد؛ تغییر مسیر `MOVED`/`ASK`. *مالک: I-16.*

<a id="hash-slot"></a>
### hash slot
یکی از ۱۶٬۳۸۴ سطل: `CRC16(key) mod 16384`. عمیق‌تر: hash tag `{…}` کلیدهای مرتبط را کنار هم نگه می‌دارد. *مالک: I-16.*

<a id="rdb-aof"></a>
### RDB / AOF
ماندگاری Redis: RDB عکس لحظه‌ای است و AOF لاگ دستورهای نوشتن. عمیق‌تر: `appendfsync always/everysec/no`. *مالک: I-16.*

<a id="ttl"></a>
### TTL — زمان زندگی
عمری که پس از آن داده خودکار منقضی می‌شود. عمیق‌تر: `EXPIRE` در Redis، TTL در Cassandra، نمایهٔ TTL در MongoDB. *مالک: I-16.*

<a id="pub-sub"></a>
### pub/sub
پیام‌رسانی انتشار و اشتراک بدون ذخیره. عمیق‌تر: مشترک آفلاین پیام را از دست می‌دهد؛ برای ماندگاری stream. *مالک: I-16.*

<a id="newsql"></a>
### NewSQL / distributed SQL — SQL توزیع‌شده
پایگاه‌هایی که SQL و ACID را نگه می‌دارند و با بازه‌های همانندسازی‌شده با اجماع مقیاس افقی می‌گیرند. عمیق‌تر: Spanner، CockroachDB، TiDB، YugabyteDB. *مالک: I-16.*

<a id="bloom-filter"></a>
### Bloom filter — فیلتر Bloom
ساختار فشرده‌ای که می‌گوید «قطعاً نیست» یا «شاید هست». عمیق‌تر: نرخ مثبت کاذب حدود `(1 − e^(−kn/m))^k`. *مالک: I-16.*

<a id="hash-tag"></a>
### hash tag
متن درون `{…}` در کلید Redis، تنها بخشی که برای یافتن slot هش می‌شود. *مالک: I-16.*

<a id="avro"></a>
### Avro
قالب دودویی فشردهٔ سطری با طرح تعبیه‌شده یا ثبت‌شده. عمیق‌تر: قالب معمول Kafka با Schema Registry. *مالک: I-16.*

<a id="protobuf"></a>
### Protobuf
Protocol Buffers: قالب دودویی مبتنی بر طرح از Google. عمیق‌تر: شماره فیلد تکامل را ممکن می‌کند. *مالک: I-16.*

<a id="subject"></a>
### subject
نامی در Schema Registry که نسخه‌های یک طرح زیر آن ذخیره می‌شود (معمولاً `<topic>-value`). *مالک: I-16.*

## I-17 مقایسهٔ گویش‌ها

<a id="dialect"></a>
### dialect — گویش
نوع SQL یک موتور. عمیق‌تر: تفاوت در املا، معناشناسی و قابلیت. *مالک: I-17.*

<a id="quoting"></a>
### quoting — نقل‌قول شناسه
پیچاندن شناسه تا نویسه‌های خاص، فاصله و کلمات رزروشده مجاز شوند. عمیق‌تر: `[ ]`، `" "` یا بک‌تیک؛ نویسهٔ بستن برای escape دوبرابر می‌شود. *مالک: I-17.*

<a id="case-folding"></a>
### case folding — تبدیل حروف
تبدیل شناسه‌های بدون نقل‌قول به یک حالت. عمیق‌تر: بزرگ در Oracle و Snowflake، کوچک در PostgreSQL و Cassandra، حفظ در بقیه. *مالک: I-17.*

<a id="batch-separator"></a>
### batch separator — جداکنندهٔ دسته
واژهٔ سمت کلاینت که گروهی از دستورها را که با هم فرستاده می‌شوند پایان می‌دهد. عمیق‌تر: `GO`، `/`، `DELIMITER`؛ سرور نمی‌فهمد. *مالک: I-17.*

<a id="go"></a>
### GO
جداکنندهٔ دستهٔ SQL Server در SSMS و `sqlcmd`، اختیاراً `GO n`. عمیق‌تر: متغیرها از آن عبور نمی‌کنند. *مالک: I-17.*

<a id="delimiter"></a>
### DELIMITER
فرمان کلاینت MySQL که پایان‌دهندهٔ دستور را عوض می‌کند. عمیق‌تر: دور بدنهٔ رویه‌ها لازم است. *مالک: I-17.*

<a id="t-sql"></a>
### T-SQL
Transact-SQL، گویش و زبان رویه‌ای SQL Server. *مالک: I-17.*

<a id="pl-sql"></a>
### PL/SQL
زبان رویه‌ای Oracle. عمیق‌تر: بلوک، package، `DBMS_OUTPUT`، ref cursor. *مالک: I-17.*

<a id="pl-pgsql"></a>
### PL/pgSQL
زبان رویه‌ای پیش‌فرض PostgreSQL. عمیق‌تر: بدنه در `$$…$$`، `RAISE NOTICE`. *مالک: I-17.*

<a id="cql"></a>
### CQL
زبان پرس‌وجوی Cassandra: شبیه SQL، بدون join و فیلتر دلخواه. عمیق‌تر: کلید پارتیشن لازم است. *مالک: I-17.*

<a id="duckdb-sql"></a>
### DuckDB SQL
گویش شبیه PostgreSQL موتور تحلیلی تعبیه‌شدهٔ DuckDB. عمیق‌تر: Rowlit برای پایگاه‌های پیوندی از آن استفاده می‌کند. *مالک: I-17.*

<a id="auto-increment"></a>
### auto_increment
ویژگی ستون MySQL که عددهای صحیح صعودی تولید می‌کند. عمیق‌تر: با `LAST_INSERT_ID()` خوانده می‌شود. *مالک: I-17.*

<a id="serial"></a>
### serial
میان‌بر قدیمی PostgreSQL برای ستون صحیح با پیش‌فرض sequence. عمیق‌تر: ستون‌های identity جانشین آن شده‌اند. *مالک: I-17.*

<a id="identity-column"></a>
### identity column — ستون identity
ستون استاندارد SQL که مقدارهایش تولید می‌شود. عمیق‌تر: `GENERATED … AS IDENTITY`؛ `IDENTITY(1,1)` در SQL Server. *مالک: I-17 (همچنین I-04).*

<a id="keyspace"></a>
### keyspace
فضای نام سطح بالای Cassandra که جدول‌ها و تنظیم همانندسازی را دارد. عمیق‌تر: مثل پایگاه داده عمل می‌کند. *مالک: I-17.*

<a id="udt"></a>
### UDT — نوع تعریف‌شده توسط کاربر
نوع مرکب سفارشی. عمیق‌تر: `address` در Cassandra، نوع‌های مرکب PostgreSQL، نوع‌های alias و جدولی SQL Server. *مالک: I-17.*

<a id="warehouse"></a>
### warehouse — انبار
در Snowflake خوشهٔ محاسباتی که پرس‌وجو اجرا می‌کند (virtual warehouse را ببینید). عمیق‌تر: برای `INFORMATION_SCHEMA` و پرس‌وجوی داده باید روشن باشد. *مالک: I-17 (ببینید I-15).*

<a id="search-path"></a>
### search_path
فهرست مرتب schemaها در PostgreSQL برای حل نام‌های بدون پیشوند. عمیق‌تر: پیش‌فرض `"$user", public`. *مالک: I-17.*

<a id="information-schema"></a>
### information_schema
مجموعهٔ استاندارد viewهای فراداده. عمیق‌تر: در PostgreSQL، MySQL، SQL Server، Snowflake. *مالک: I-17.*

<a id="sys-catalog-views"></a>
### sys catalog views — viewهای کاتالوگ sys
viewهای کاتالوگ SQL Server (`sys.tables`، `sys.columns`، `sys.objects`). عمیق‌تر: غنی‌تر از `INFORMATION_SCHEMA`. *مالک: I-17.*

<a id="pg-catalog"></a>
### pg_catalog
کاتالوگ سیستمی PostgreSQL (`pg_class`، `pg_attribute`، `pg_namespace`). عمیق‌تر: آنچه `psql` می‌خواند. *مالک: I-17.*

<a id="all-views"></a>
### ALL_* views — viewهای ALL_*
viewهای فرهنگ داده Oracle: `USER_*` (مال شما)، `ALL_*` (قابل دیدن برای شما)، `DBA_*` (همه). *مالک: I-17.*

<a id="sqlite-master"></a>
### sqlite_master
جدول اشیای schema در SQLite (و `sqlite_schema`). عمیق‌تر: با توابع `pragma_*` ترکیب می‌شود. *مالک: I-17.*

<a id="system-tables"></a>
### system.* tables — جدول‌های system.*
جدول‌های فراداده و پایش ClickHouse (`system.tables`، `system.parts`، `system.query_log`). *مالک: I-17.*

<a id="system-schema"></a>
### system_schema
keyspace جدول‌های schema در Cassandra (`keyspaces`، `tables`، `columns`). عمیق‌تر: بر اساس keyspace پارتیشن‌بندی شده. *مالک: I-17.*
